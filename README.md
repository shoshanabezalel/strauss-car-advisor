# יועץ הרכב של שטראוס

עובד שטראוס שואל בעברית "מה יקרה לנטו שלי אם אחליף את רכב החברה או אוותר עליו?", ומקבל תשובה מדויקת לפי כללי החברה.

**האתר החי:** https://strauss-car-advisor-smoky.vercel.app

## איך מנסים

1. **מסך העובד:** נכנסים לאתר ולוחצים **להתחלת שיחה**. כותבים, למשל:
   "שכר בסיס 18,000, קבוצה ג, 2 ילדים, יש לי היום BYD ATTO 3. כמה יישאר לי בנטו אם אוותר על הרכב?"
   אפשר גם לצרף תלוש שכר.
2. **חיפוש לפי תנאים:** אחרי שהפרטים מולאו, כותבים:
   "אני רוצה רכב חשמלי, אבל שהנטו לא ירד ביותר מ־100 ₪ בחודש"
3. **מסך צוות הרכב:** פותחים את `/rep` בלשונית נוספת. קוד הגישה נמצא בטופס ההגשה. עונים על שאלה פתוחה, ומסך העובד מתעדכן בלי רענון.

## מה המערכת עושה

- שיחה בעברית עם סוכן AI ששואל רק את מה שחסר.
- העלאת תלוש שכר: הערכים נקראים מהתלוש, והעובד מאשר כל אחד מהם.
- כרטיסי השוואה בתוך השיחה: הנטו היום מול כל חלופה, עם "איך זה מחושב?" שמפרט כל רכיב.
- חיפוש לפי תנאים: סוג הנע, כמה הנטו יכול לרדת, השתתפות מקסימלית.
- שאלות לצוות הרכב, והתשובה מגיעה לעובד בזמן אמת.
- יומן פערי מידע לצוות הרכב.
- סיור היכרות קצר בכניסה הראשונה.
- תצוגת טלפון.

## ארכיטקטורה

העובד מדבר בעברית עם סוכן AI (Gemini), או מעלה תלוש שכר. הסוכן לא מחשב: הוא מתרגם את הבקשה לפרמטרים, ומנוע חישוב דטרמיניסטי מחשב את הנטו, הזכאות והחלופות לפי קובץ כללים. כך אפשר גם לבקש בשפה חופשית "רכב חשמלי, בלי ירידה של יותר מ־100 ₪", והמנוע מסנן את הרכבים שעומדים בתנאי. כשחסר נתון, הסוכן אומר שאינו יודע או שולח שאלה לצוות הרכב, שעונה בזמן אמת. נבנה ב־Next.js, Supabase ו־Vercel, עם Claude Code: תוכנית, טסטים לפני קוד, מימוש ו־CI.

מסמכים: [SPEC](docs/SPEC.md) · [ARCHITECTURE](docs/ARCHITECTURE.md) · [TECH-DESIGN](docs/TECH-DESIGN.md) · [PLAN](docs/PLAN.md) · [AI-PROCESS](docs/AI-PROCESS.md)

## הפיצ'ר המקורי: יומן פערי מידע

- **מה:** בכל פעם שהמערכת לא יכולה לענות מנתונים אמיתיים, היא רושמת את הפער: השתתפות שלא אושרה, שאלה שנשלחה לצוות הרכב, רכב שאינו בקטלוג, שאלה שאין לה כלל.
- **למה:** שטראוס רואה בדיוק מה חסר בקטלוג ובכללים, ויכולה להשלים. נרשם מידע של החברה בלבד, בלי פרטים אישיים.
- **איך מנסים:** במסך `/rep`, לשונית **פערי מידע**: קיבוץ לפי נושא, ניתוח AI שמצטט רק מספרים מהסיכום, וייצוא CSV.

## אמינות

- המודל אף פעם לא כותב מספר שהמנוע לא חישב. בודק מספרים בקוד דוחה כל תשובה עם מספר שאינו בתוצאות הכלים, וכרטיסי ההשוואה נבנים ישירות מהמנוע.
- המנוע נבדק מול 6 העובדים לדוגמה של שטראוס (גיליון "חישובים"), והתוצאות זהות.
- טסטים: 628 טסטי יחידה, 39 טסטי e2e (ריצת ה־CI הירוקה האחרונה), 16 בדיקות חיות מול המודל (16/16).

## מגבלות ידועות

- הנטו הוא הערכה לפי כללי החברה וטבלאות המס של 2026, מעוגל לשקל. אין חיבור למערכת שכר (נתוני הדגמה מקובצי האתגר).
- צוות הרכב נכנס עם קוד משותף אחד. בפיילוט נדרשת כניסה אישית.
- שיחה נפתחת רק בדפדפן שהתחיל אותה.
- קריאת התלוש נעשית במודל; העובד מאשר כל ערך, וערך לא ברור נשאר ריק. הקובץ לא נשמר.
- הסוכן החי תלוי ב־Gemini API (יש מודל גיבוי), ויש הגבלת קצב לכל מבקר.
- עברית בלבד. טרם נבדק עם עובדים אמיתיים.

## הרצה מקומית

נדרש Node 22 ומעלה.

```bash
npm install
cp .env.example .env.local   # fill in the values
npx playwright install chromium
```

מסד הנתונים: מחילים את [supabase/migrations/](supabase/migrations/) על פרויקט Supabase, ואז:

```bash
npm run import:vou   # load the tax-authority value-of-use CSV
npm run check:db     # check tables, RLS and value-of-use lookup
```

הרצה ובדיקות:

```bash
npm run dev          # http://localhost:3000
npm test             # unit tests (Vitest)
npm run test:e2e     # e2e tests (Playwright)
npm run eval:agent   # live agent evals (needs GOOGLE_GENERATIVE_AI_API_KEY)
npm run typecheck
```

בלי גישה למודל:

```bash
AGENT_MODEL=mock npm run dev
```
